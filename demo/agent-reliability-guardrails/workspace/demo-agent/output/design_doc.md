# 短链接服务技术设计文档

## 1. 背景
随着信息分享的快速发展，短链接服务已成为 URL 管理的重要组成部分。其主要目的是将冗长的 URL 转换成短小的、易于分享的链接。本技术设计文档针对构建一个短链接服务的技术细节进行深入探讨。

## 2. 目标
### 必须完成的目标
- 实现一个可用于生成短链接的 API 接口。
- 提供查找短链接的功能，能够解析短链接为原始 URL。
- 支持自定义短链接功能。

### 暂不处理的范围
- 用户管理和权限控制尚未纳入当前范围。
- 统计功能将在未来版本中实现。

## 3. 约束
- **运行环境**: 服务应在云环境中部署，支持 Docker 容器。
- **依赖**: Redis 作为缓存，MySQL 作为主存储。
- **权限边界**: 只有授权用户可以访问 API。
- **数据输入输出**: 输入为原始 URL，输出为短链接。
- **可靠性要求**: 服务需保证 99.9% 的可用性。
- **敏感目录**: 不得直接操作系统文件和数据库目录。

## 4. 方案
### 模块职责
- **API 模块**: 接受请求并路由到相应的处理逻辑。
- **短链接生成模块**: 负责生成唯一的短链接。
- **查询模块**: 接受短链接并返回对应的原始 URL。

### 关键流程
1. 用户提交原始 URL，API 模块接收请求。
2. 短链接生成模块验证 URL 有效性，并生成唯一短链接。
3. 将短链接和原始 URL 存储到数据库中。
4. 用户通过短链接请求原始 URL，API 模块查询数据库并返回结果。

### 数据结构
```json
{
  "short_url": "abc123",
  "original_url": "http://www.example.com/long-url",
  "created_at": "2023-10-25T12:00:00Z"
}
```

### 接口约定
- `POST /shorten` - 创建短链接
  - 请求体: `{ "url": "http://www.example.com/long-url" }`
  - 响应体: `{ "short_url": "abc123" }`

- `GET /resolve/{short_url}` - 解析短链接
  - 响应体: `{ "original_url": "http://www.example.com/long-url" }`

## 5. 风险
- **路径逃逸**: 确保输入 URL 经过严格验证，防止路径穿越攻击。
- **权限过宽**: 限制 API 访问权限，避免未授权用户调用。
- **超时**: 响应时间应设置超时机制，保证服务的稳定性。
- **外部命令失败**: 避免依赖外部服务，确保短链接服务自给自足。
- **观测缺失**: 实时监控 API 的性能指标和异常日志。
- **状态不一致**: 在生成短链接与数据存储时应采用事务机制。

## 6. 验证
- **验证命令**:  使用 Postman 或 curl 测试 API。
  - 请求: `curl -X POST http://localhost:8080/shorten -d '{"url":"http://www.example.com/long-url"}'`
  - 预期结果: `{ "short_url": "abc123" }`
