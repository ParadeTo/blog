# 技术设计文档 SOP

使用本 Skill 时，必须写设计文档，并把最终交付物保存为 `design_doc.md`。

## 1. 背景

说明任务来源、业务目标、读者需要解决的问题，以及当前系统中已经存在的相关能力。

## 2. 目标

列出本次设计要达成的结果，区分必须完成和暂不处理的范围。

## 3. 约束

写清楚运行环境、依赖、权限边界、数据输入输出、可靠性要求和不能触碰的目录。

## 4. 方案

描述模块职责、关键流程、数据结构和接口约定。必要时补充伪代码，但不要隐藏重要判断。

## 5. 风险

列出可能失败的地方，例如路径逃逸、权限过宽、超时、外部命令失败、观测缺失和状态不一致。

## 6. 验证

给出最小可复现的验证命令、预期结果和失败时应该检查的线索。

## 7. 交付

把最终内容写入 `design_doc.md`，并确保文件位于受控输出目录中。
