# 项目需求文档

## 项目背景

用户在日常工作中有大量待办事项，目前依赖便利贴和备忘录管理，存在容易遗忘、优先级混乱等痛点。为此，需要开发一个命令行版智能待办事项助手，帮助用户快速录入、管理和追踪待办任务。

## 目标

**要解决的问题：**
- 待办事项分散、容易遗忘
- 优先级管理混乱，不知道先做什么

**成功标准：**
- 用户可在 30 秒内完成一个任务的录入
- 任务列表按截止时间和优先级排序展示
- 支持至少 100 个并发任务不卡顿
- 命令行界面，无需 GUI

## 边界

### 范围内
- 添加任务：用自然语言描述，系统自动提取标题和截止时间
- 查看列表：按优先级展示未完成任务
- 标记完成：将任务标记为已完成状态
- 智能提醒：任务临近截止时提示用户

### 范围外
- 图形界面（GUI）
- 外部数据库集成（仅本地文件存储）
- 多人协作 / 团队共享功能（未提及，默认不做）
- 移动端 / Web 端支持

## 约束

- **技术栈**：Node.js
- **存储方式**：本地文件存储，不依赖外部数据库
- **团队规模**：单人开发
- **交付周期**：预计 2 周完成

## 风险

1. **自然语言解析准确率**：从自然语言中自动提取标题和截止时间，依赖 NLP 或规则解析，准确率可能不稳定，需明确兜底策略（如解析失败时手动输入）
2. **智能提醒机制**：命令行工具通常无常驻进程，"临近截止提醒"的触发方式需明确（如每次启动时检查 vs. 系统定时任务 cron）
3. **2 周工期较紧**：功能点含自然语言解析和提醒机制，单人 2 周存在一定风险，建议明确 MVP 优先级

## 待澄清（需 Human 确认）

1. **自然语言解析失败时的兜底方案**：当系统无法从描述中提取截止时间时，是报错提示用户手动补充，还是允许无截止时间的任务存在？
2. **智能提醒的触发机制**：是每次运行命令时检查并提示，还是需要后台常驻进程 / 系统 cron 定时推送？
3. **优先级的设定方式**：优先级是用户手动指定（如 high/medium/low），还是系统根据截止时间自动计算？
4. **"并发任务"的含义**：需求中提到"支持至少 100 个并发任务不卡顿"，此处"并发"是指同时存在 100 条未完成任务，还是有其他含义？
